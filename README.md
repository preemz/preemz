# Hi, I'm Primawan

I run a recruiting company and build the software it runs on.

By day I'm a founder: Satrio Consulting places talent across the Indonesia-Japan corridor and into EU companies, and KerjaBoard (apply.satriocs.com) is the job board and candidate pipeline I built to run it. It handles CV parsing, candidate scoring, and GDPR compliance for EU postings. All of it runs on Cloudflare Workers with no origin server.

The unusual part of my path: I spent 10+ years in recruitment before writing most of this code. I was a PM at Bukalapak (Indonesia's largest e-commerce) before that, and a recruiter in Tokyo before that. So when I build recruiting software, I'm building against problems I've personally had, not problems I imagine recruiters have.

What I care about in code: knowing which problems need a model and which need a regex. I wrote up my thinking in a few posts:

- [An end-to-end AI recruiting pipeline in production](https://preemz.github.io/blog-ai-recruiting-pipeline.html) — LLM resume parsing, explainable fit scoring, and why every score ships with its reasons
- [Importing thousands of candidates without breaking a single record](https://preemz.github.io/blog-csv-candidate-import.html) — CSV parsing, bilingual column mapping, and deduplication on email as the identity key
- [Observability on a Workers free plan](https://preemz.github.io/blog-workers-observability.html) — what we did when there was no APM, and what upgrading actually unlocked
